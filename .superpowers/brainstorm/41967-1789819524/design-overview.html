Design: Sleep & Background Detection

Full design for review — does this match what you have in mind?

How it works
Behaviour flow
  1. When collection starts, Cutie attaches a visibilitychange listener
  2. The moment the page is hidden (lid closes / screen locks / tab switch), a 30-second countdown starts
  3. If the page becomes visible again within 30s → countdown cancelled, collection continues normally
  4. If still hidden after 30s → disconnect('sleep') fires, probes stop cleanly
  5. The listener is removed when collection stops (any reason)
What the user sees
Mobile (phone / tablet)
Start
Collection stopped — Cutie only works when visible

Triggered when: tab switches to another app/browser window

Non-mobile (desktop / laptop)
Start
Collection stopped — computer went to sleep

Triggered when: lid closes, screen locks, or computer sleeps

Code changes — all in webrtc.ts
What changes
  • Add 'sleep' to the DisconnectReason type
  • Add isMobile() helper — checks navigator.maxTouchPoints > 0 + user agent
  • Add scheduleVisibilityStop() — 30s timer on hide, cancelled on show
  • Attach listener in beginCollectionSession(), remove in disconnect()
  • Handle 'sleep' in the message block of disconnect()

No changes needed to the UI, charts, stores, or probe logic.

Edge cases handled
Scenarios
Scenario Result
Brief tab switch (<30s) Collection continues
Lid closed / screen locked >30s Clean stop, green banner
User clicks Stop before 30s elapses Manual stop wins, timer cancelled
2-hour auto-stop fires while hidden Auto-stop wins, existing message shown
Connection error while hidden Error stop wins, red banner
