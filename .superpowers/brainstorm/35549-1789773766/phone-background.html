Can Cutie keep testing on a phone when another tab is in front?

Short answer: on iOS, no. On Android, maybe — with caveats.

Why it's hard
What mobile browsers do when you switch tabs
Browser JS timers WebRTC data channel Web Workers
iOS Safari Frozen immediately Often closed Also frozen
Chrome / Android Throttled ~1/min Usually stays open May keep running
Firefox / Android Throttled Usually stays open Throttled

The probe sender uses setInterval — it cannot run reliably in a background tab on any mobile browser. Even if the data channel stays open, Cutie cannot send probes.

Options
A

Same as desktop — Detect & Stop on hide

When the tab goes to background, stop collection. Show: "Collection stopped — Cutie needs to stay in the foreground." Consistent behavior everywhere. Simple.

Pros

  • Zero extra complexity
  • Honest message to user
  • Consistent across all platforms

Cons

  • Can't run speed test alongside
B

PWA / Add to Home Screen hint

Same as A, but show a one-time banner on mobile: "Tip: Add Cutie to your home screen — it gets its own window and stays visible while you use the browser." On Android, a PWA in its own window doesn't compete with the browser tab.

Pros

  • Practical workaround on Android
  • No code changes to core logic

Cons

  • Doesn't help iOS
  • Requires PWA manifest setup
C

Screen Wake Lock (keep-awake, no tab switch)

Use navigator.wakeLock.request('screen') while collecting. This prevents the screen from going to sleep while Cutie is the active tab. It does not help when switching tabs — but it means the phone won't auto-sleep while Cutie is running.

Pros

  • Keeps screen on during collection
  • Small, self-contained addition
  • Supported on Chrome/Android & Safari 16.4+

Cons

  • Drains battery faster
  • Doesn't help tab-switch scenario

Options are independent — you can do A + B, A + C, or all three. Click all that interest you.
